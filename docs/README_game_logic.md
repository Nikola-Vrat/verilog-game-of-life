# Описание модуля `game_logic`

## 1. Назначение модуля

Модуль `game_logic` реализует основную логику игры **«Жизнь»** на игровом поле размером **10×10 клеток**.

Модуль выполняет следующие функции:

- принимает начальное состояние игрового поля;
- сохраняет последнее загруженное состояние;
- формирует следующее поколение клеток в соответствии с правилами игры «Жизнь»;
- поддерживает тороидальное соединение границ игрового поля;
- восстанавливает последнее загруженное состояние при сбросе;
- передаёт текущее состояние игрового поля на выход;
- формирует сигнал для перезапуска таймера после загрузки новой матрицы.

---

## 2. Параметры модуля

В модуле используются два параметра:

```verilog
parameter W = 10,
parameter H = 10
```

- `W` — ширина игрового поля;
- `H` — высота игрового поля.

При значениях `W = 10` и `H = 10` поле содержит:

```text
10 × 10 = 100 клеток
```

Каждая клетка может находиться в одном из двух состояний:

- `1` — клетка живая;
- `0` — клетка мёртвая.

---

## 3. Входные сигналы

### `clk`

Тактовый сигнал модуля.

По его положительному фронту выполняются изменения состояния игрового поля.

### `rst`

Сигнал сброса.

При его активации текущее игровое состояние восстанавливается из сохранённой матрицы `saved_state`.

### `cr_new_gen`

Импульс перехода к следующему поколению.

При его активации `current_grid` заменяется рассчитанным значением `next_grid`.

### `init_state`

Входная шина, содержащая новую начальную матрицу игрового поля.

Для поля 10×10 её размер составляет:

```text
W × H = 100 бит
```

Матрица поступает в модуль от блока, отвечающего за формирование начального состояния.

### `all_data_transmited`

Сигнал сообщает о завершении передачи всей начальной матрицы.

После получения этого сигнала модуль подготавливает загрузку нового состояния игрового поля.

---

## 4. Выходные сигналы

### `generation_triggers`

Выходная шина размером `W × H` бит.

Она содержит текущее состояние игрового поля и используется для передачи информации о состоянии каждой клетки другим блокам проекта.

Для поля 10×10 размер шины составляет **100 бит**.

### `restart_timer`

Сигнал команды перезапуска таймера.

Он формируется после завершения загрузки нового состояния и может использоваться модулем делителя частоты для начала отсчёта времени до следующего поколения.

---

## 5. Внутренние регистры

### `current_grid`

```verilog
reg [W-1:0] current_grid [0:H-1];
```

Хранит текущее состояние игрового поля.

Каждый элемент массива представляет одну строку поля, состоящую из `W` клеток.

Для поля 10×10 используется 10 строк по 10 бит:

```text
current_grid[0]
current_grid[1]
...
current_grid[9]
```

### `saved_state`

```verilog
reg [W-1:0] saved_state [0:H-1];
```

Хранит последнее успешно загруженное начальное состояние.

Это состояние не изменяется во время обычного выполнения игры. Оно используется для восстановления исходной матрицы при сбросе.

### `next_grid`

```verilog
wire [W-1:0] next_grid [0:H-1];
```

Содержит рассчитанное следующее поколение игрового поля.

Значения `next_grid` формируются комбинационной логикой на основании текущего состояния `current_grid`.

### `load_state_pending`

```verilog
reg load_state_pending;
```

Используется для задержки сигнала `all_data_transmited` на один такт.

Это необходимо для того, чтобы после завершения передачи данные в `init_state` успели полностью сформироваться перед их загрузкой в `current_grid`.

---

## 6. Формирование сигнала `load_state_pending`

Сигнал формируется следующим блоком:

```verilog
always @(posedge clk or posedge rst) begin
    if (rst)
        load_state_pending <= 1'b0;
    else
        load_state_pending <= all_data_transmited;
end
```

При каждом положительном фронте тактового сигнала значение `all_data_transmited` записывается в `load_state_pending`.

Таким образом, `load_state_pending` представляет собой задержанную на один такт версию `all_data_transmited`.

После этого:

```verilog
assign restart_timer = load_state_pending;
```

Сигнал передаётся на выход `restart_timer`.

---

## 7. Расчёт соседних клеток

Для каждой клетки игрового поля определяется восемь соседей.

Для этого используются параметры:

```verilog
ym
yp
xm
xp
```

Они определяют координаты верхней, нижней, левой и правой соседних клеток соответственно.

Например:

```verilog
localparam ym = (y == 0) ? H - 1 : y - 1;
```

Если текущая клетка находится в первой строке, верхней строкой считается последняя строка поля.

Аналогично обрабатываются остальные границы.

Таким образом реализуется **тороидальное игровое поле**: верхняя граница соединена с нижней, а левая — с правой.

---

## 8. Подсчёт живых соседей

Для каждой клетки вычисляется количество живых соседей:

```verilog
wire [3:0] neighbors;

assign neighbors =
    current_grid[ym][xm] +
    current_grid[ym][x]  +
    current_grid[ym][xp] +
    current_grid[y][xm]  +
    current_grid[y][xp]  +
    current_grid[yp][xm] +
    current_grid[yp][x]  +
    current_grid[yp][xp];
```

Так как у клетки 8 соседей, для хранения результата достаточно 4 бит.

Полученное значение `neighbors` используется для определения состояния клетки в следующем поколении.

---

## 9. Правила игры «Жизнь»

Следующее состояние клетки определяется выражением:

```verilog
assign next_grid[y][x] =
    current_grid[y][x] ?
    (neighbors == 4'd2 || neighbors == 4'd3) :
    (neighbors == 4'd3);
```

Используется стандартное правило игры **«Жизнь» Конвея**.

### Для живой клетки

- при двух живых соседях она остаётся живой;
- при трёх живых соседях она остаётся живой;
- при любом другом количестве соседей она погибает.

### Для мёртвой клетки

- если имеется ровно три живых соседа, она становится живой;
- во всех остальных случаях остаётся мёртвой.

Таким образом формируется матрица `next_grid`, содержащая следующее поколение.

---

## 10. Переход к следующему поколению

Переход выполняется в синхронном блоке:

```verilog
else if (cr_new_gen) begin
    for (r_idx = 0; r_idx < H; r_idx = r_idx + 1) begin
        current_grid[r_idx] <= next_grid[r_idx];
    end
end
```

При поступлении импульса `cr_new_gen` каждая строка текущего поля заменяется соответствующей строкой `next_grid`.

Таким образом:

```text
current_grid → next_grid
```

После выполнения перехода `current_grid` содержит новое поколение игрового поля.

---

## 11. Загрузка новой матрицы

Когда поступает сигнал `load_state_pending`, новая матрица загружается одновременно в два массива:

```verilog
current_grid[r_idx] <=
    init_state[(H - 1 - r_idx) * W +: W];

saved_state[r_idx] <=
    init_state[(H - 1 - r_idx) * W +: W];
```

В `current_grid` записывается текущее состояние игры.

Одновременно это же состояние сохраняется в `saved_state`.

Поэтому после загрузки:

```text
current_grid = новая матрица
saved_state  = новая матрица
```

Во время работы игры `current_grid` изменяется, а `saved_state` остаётся неизменным.

---

## 12. Восстановление состояния при сбросе

При активации `rst` выполняется:

```verilog
if (rst) begin
    for (r_idx = 0; r_idx < H; r_idx = r_idx + 1) begin
        current_grid[r_idx] <= saved_state[r_idx];
    end
end
```

Таким образом, текущее состояние заменяется последним сохранённым состоянием, которое было получено при загрузке новой матрицы.

Это позволяет после сброса вернуть игровое поле к последней загруженной начальной конфигурации.

---

## 13. Формирование выходной матрицы

Текущее состояние каждой клетки передаётся на `generation_triggers`:

```verilog
assign generation_triggers[(H - 1 - y) * W + x] =
    current_grid[y][x];
```

При формировании выходной шины выполняется перестановка строк, необходимая для соответствия внутреннего представления матрицы формату, используемому остальными блоками проекта.

Для поля 10×10 итоговая шина содержит **100 бит**.

## 15. Взаимодействие с другими блоками

Модуль `game_logic` является вычислительной частью проекта.

Он получает готовое начальное состояние через `init_state`, после чего самостоятельно:

1. загружает начальную матрицу;
2. сохраняет её в `saved_state`;
3. рассчитывает количество живых соседей;
4. формирует `next_grid`;
5. по импульсу `cr_new_gen` переходит к следующему поколению;
6. передаёт текущее состояние через `generation_triggers`;
7. формирует `restart_timer` после загрузки новой матрицы.
